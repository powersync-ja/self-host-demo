# JavaScript PowerSync + MongoDB Replication Pre-filtering Demo

This demo extends the [MongoDB demo](../nodejs-mongodb/README.md) with MongoDB Replication Pre-filtering. Pre-filtering excludes source documents before they are replicated, so they never reach bucket storage: excluded documents are skipped during the initial snapshot, and during change-stream replication. This feature is only available for customers on [Team and Enterprise](https://www.powersync.com/pricing) plans.

The filter used here keeps documents with `archived: false`, configured in [`powersync/sync-config.yaml`](./powersync/sync-config.yaml):

```yaml
config:
  edition: 3
  source_table_options:
    lists:
      mongodb_filter_expression:
        $eq: ['$$doc.archived', false]
    todos:
      mongodb_filter_expression:
        $eq: ['$$doc.archived', false]
```

Source-table option keys can be unqualified (`lists`) or fully qualified (`connection.database.table`). Here, `default` is the tag of the untagged MongoDB connection in `service.yaml`, and `powersync_demo_backend` is the source database.

Filters only support operators that can use an index during the initial snapshot (`$eq`, `$in`, `$and`, and `$or`), so `archived != true` can't be directly expressed. The filter matches only an explicit `archived: false`: a document without an `archived` field is excluded, just like an archived one. The seed and stream writer therefore always set `archived` to `true` or `false`.

The sync stream queries deliberately don't filter on `archived`; MongoDB Replication Pre-filtering handles that.

## Environment

The existing `.env` file configures the MongoDB source connection, backend and client ports, and authentication settings. These values can be adjusted for your local setup:

```bash
PS_DATA_SOURCE_URI=mongodb://mongo:27017/powersync_demo_backend

DEMO_BACKEND_PORT=6060
DEMO_BACKEND_DATABASE_TYPE=mongodb
DEMO_BACKEND_DATABASE_URI=${PS_DATA_SOURCE_URI}
DEMO_CLIENT_PORT=3038
PS_JWKS_URL=http://demo-backend:${DEMO_BACKEND_PORT}/api/auth/keys

# These can be generated by following the instructions in the `key-generator` folder
# A temporary key will be used if these are not specified
DEMO_JWKS_PUBLIC_KEY=
DEMO_JWKS_PRIVATE_KEY=

PS_PORT=8080
```

The seed and stream writer settings in [`docker-compose.yaml`](./docker-compose.yaml) have defaults, and can be overridden in `.env`:

| Variable                | Default                                | Description                                                                                                      |
| ----------------------- | -------------------------------------- | ---------------------------------------------------------------------------------------------------------------- |
| `SEED_LISTS`            | `20`                                   | Number of seeded lists. Keep this small, since the app shows every active list                                   |
| `SEED_TODOS_PER_LIST`   | `800`                                  | Todos per seeded list                                                                                            |
| `SEED_ARCHIVED_RATIO`   | `0.5`                                  | Fraction of lists, and of todos in active lists, which are archived. Todos in archived lists are always archived |
| `SEED_BATCH_SIZE`       | `5000`                                 | Documents per `insertMany`                                                                                       |
| `STREAM_BATCHES`        | `20`                                   | Batches written by the stream writer                                                                             |
| `STREAM_BATCH_SIZE`     | `1000`                                 | Todos inserted per batch                                                                                         |
| `STREAM_ARCHIVED_RATIO` | `0.9`                                  | Fraction of inserted todos which are archived                                                                    |
| `STREAM_INTERVAL_MS`    | `1000`                                 | Delay between batches                                                                                            |

## Running

Compose runs the JavaScript scripts in [`scripts/`](./scripts) with `mongosh` inside the `mongo:7.0` containers. They use shell globals such as `db`, `load`, and `print`. Shared utilities, including document creation, environment settings, replica-set readiness, random generation, and source counts, live in [`scripts/common.js`](./scripts/common.js).

This demo can be started by running the following in this demo directory

```bash
docker compose up
```

or in the root directory run

```bash
docker compose -f demos/nodejs-mongodb-prefiltering/docker-compose.yaml up
```

Startup order:

1. `mongo` and `mongo-rs-init` start the MongoDB replica set.
2. `seed` inserts archived and non-archived `lists` and `todos` into the source database, then exits. Every document has an explicit `archived: true` or `archived: false`. It also creates an `{ archived: 1, _id: 1 }` index on both collections, which the filtered snapshot uses: it queries `archived: false` and pages in `_id` order, so each page reads only the documents it returns. The seed only runs against an empty database.
3. `powersync` starts only after `seed` completes, so the initial snapshot has to filter the full seeded backlog.

The frontend can be accessed at `http://localhost:3038` in a browser.

### Snapshot

With the defaults, 12 of the 20 seeded lists and roughly 4,800 of the 16,000 seeded todos are active. The split is the same on every seed with the same settings. Compare the client's counts, from the frontend's SQL console, to the source:

```sql
select count(*) from todos
```

```bash
docker compose run --rm stats
```

`stats` prints the total, archived, and active (expected to sync) counts for each collection. It also reports documents without `archived: true` or `archived: false`, for example ones edited by hand; those are excluded by the filter.

### Streaming

While PowerSync is running, write more data to the source database:

```bash
docker compose run --rm stream-writer
```

All runs share one active list, `Streamed`, and one archived list, `Archived streamed`, which should not sync. Both are created on the first run. Each batch inserts todos into the `Streamed` list: archived todos should be skipped, and active todos should sync. `STREAM_ARCHIVED_RATIO` controls the fraction of archived inserts.

Run `stats` again afterwards and compare it to the client's counts. Settings can be overridden per run, e.g.

```bash
docker compose run --rm -e STREAM_BATCHES=100 -e STREAM_INTERVAL_MS=0 stream-writer
```

Writes can also be started while the initial snapshot is still in progress.

#### Archived todos only

To add only archived todos, run the stream writer with every insert archived. None of these todos should reach the client:

```bash
docker compose run --rm -e STREAM_ARCHIVED_RATIO=1 -e STREAM_BATCHES=2 -e STREAM_INTERVAL_MS=0 stream-writer
```

This inserts 2,000 archived todos (2 batches of `STREAM_BATCH_SIZE`) into the `Streamed` list. Increase `STREAM_BATCHES` for more. The client's `select count(*) from todos` should stay the same, while `stats` shows the archived count growing.

## PowerSync CLI

[`powersync/cli.yaml`](./powersync/cli.yaml) links the PowerSync CLI to the local service, using the admin API token from `api.tokens` in [`powersync/service.yaml`](./powersync/service.yaml). With the service running, from this demo directory:

```bash
powersync validate
```

## Cleanup

To re-seed, or start fresh after changing the seed settings, remove the containers and volumes:

```bash
docker compose down -v
```
